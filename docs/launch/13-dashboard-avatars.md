# PR-11: dashboard and durable avatars

Owns FLOW-02 and OPS-02. Dashboard creation and old template links now use the shared catalog/resolver/workspace. Saved inputs and immutable versions are listed from the database, with owner-scoped reopening and export. Revising a version preserves the original. A claimed guest version starts a new owned draft instead of transferring the original guest draft. Earlier legacy records remain accessible separately. Dashboard totals now count saved versions, including unpaid drafts; they are not purchase totals.

Avatar uploads accept up to 2 MiB of JPEG/PNG/WebP bytes, bound the actual multipart body, decode with a 16-million-pixel ceiling, strip metadata and re-encode a 256px WebP. Names are random UUIDs. A private Vercel Blob store serves images through authenticated owner-only requests. Storage/database failures never return a successful upload. Pending object identities survive crashes; replaced objects are retired and removed by authenticated `/api/cron/cleanup-avatars` batches. Pending uploads older than one day can be cleaned up. This cleanup only concerns superseded/abandoned avatar uploads, not customer-document retention.

Configure a PRIVATE Vercel Blob store and connect the intended deployment/environment (`BLOB_STORE_ID` with Vercel OIDC, or `BLOB_READ_WRITE_TOKEN` outside Vercel). No store or paid resource is provisioned by this change. Existing `/uploads/avatars` files need controlled migration from their original deployment if still available; temporary files cannot be reconstructed automatically. Until configured, uploads return an honest unavailable error.

Verification: image decoding/re-encoding and cross-owner read denial tests; schema equivalence and migration preservation; typecheck/lint/build in CI. Production acceptance remains open until an authorized staging user completes create/save/reopen/export with reviewed content and uploads an avatar that survives a deployment. Existing settings APIs persist supported preferences; generation/export containment and legal-review gates remain in force.

Rollback: code rollback is additive-schema compatible. Retain private objects and StoredAvatar records; do not revert to ephemeral upload handling. Blob cleanup can be unscheduled during investigation. Source references: https://vercel.com/docs/vercel-blob/using-blob-sdk and https://sharp.pixelplumbing.com/api-constructor/.
